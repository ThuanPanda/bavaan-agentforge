## PM Agent làm được gì?

| Trước | Sau |
|---|---|
| Đọc email thủ công, tóm tắt → viết Epic | Graph MCP tự fetch + PM Agent viết draft |
| 8h/tuần viết User Stories | 3h/tuần (review + approve AI draft) |
| Sprint planning thủ công trên Excel | Sprint planner skill với capacity tự động |
| Release notes viết thủ công sau mỗi deploy | Auto-draft từ merged PRs + Monday items |
| Report stakeholder mỗi tuần tốn 2-3h | Auto-generate, PM chỉ cần review |

## Setup (30 phút — làm 1 lần)

### Bước 1: Cài Claude Desktop
- Download: https://claude.ai/download
- Đăng nhập bằng tài khoản Bavaan Claude

### Bước 2: Upload Skills
```
1. Mở Claude Desktop
2. Settings → Capabilities → Skills
3. Upload → chọn file ai-skills/v210.0/pm/bavaan-pm-skills.zip
4. Toggle ON: bavaan-pm-agent
```

### Bước 3: Cấu hình MCP
```
1. Mở Settings → Extensions
2. Connect: Monday.com (dùng Bavaan API token từ IT)
3. Connect: Microsoft Graph (xác thực bằng tài khoản Microsoft Bavaan)
4. Connect: SharePoint (tự động qua Microsoft account)
5. Verify: Hỏi Claude "List my active Monday tasks"
```

## Workflow hàng ngày

### Tình huống 1: Nhận email mới về feature request

```
Bạn: "Có email từ client về tính năng export báo cáo. 
      Dùng Graph MCP fetch email thread keyword 'export report'
      tuần này, tạo Epic trên Monday."

Claude: [Graph MCP fetch email] [Check Monday for duplicates]
        [Generate Epic structure] [Create on Monday via MCP]

Kết quả: Epic "Enable Report Export for Client Portal"
         đã có trên Monday với 5 User Stories + ACs
         Bạn chỉ cần review và adjust nếu cần
```

### Tình huống 2: Sprint planning

```
Bạn: "Sprint planning tuần tới. Team có 4 devs, 8 ngày.
      Velocity trung bình 35 points. Plan sprint từ backlog."

Claude: [Monday MCP fetch Ready stories] [Calculate capacity]
        [Assign stories respecting dependencies]

Kết quả: Sprint plan với 32-35 points, dependencies rõ ràng,
         risk distribution hợp lý
```

### Tình huống 3: Release notes sau sprint

```
Bạn: "Sprint 23 vừa xong. Draft release notes."

Claude: [GitHub MCP fetch merged PRs] [Monday MCP fetch completed stories]
        [Group by: Features, Improvements, Bugs]
        [Upload to SharePoint] [Update Monday]

Kết quả: Release notes với ngôn ngữ user-friendly, không jargon kỹ thuật
```

## Prompts chuẩn (copy & dùng)

```
# Tạo Epic từ email
"Fetch email thread về [chủ đề] từ tuần này qua Graph MCP,
kiểm tra Monday có Epic tương tự chưa, nếu chưa thì
tạo Epic mới với đầy đủ ACs và push lên Monday."

# Refine stories
"Đọc Epic [ID] trên Monday, kiểm tra từng Story có đủ
testable ACs theo format Given/When/Then chưa, refine
và update lên Monday."

# Sprint planning
"Team [N] devs, [N] ngày, velocity [N] points.
Fetch tất cả Ready stories từ Monday backlog,
plan sprint tối ưu nhất."

# Stakeholder report
"Tạo weekly report cho sprint [N]: delivered, in progress,
blockers. Upload SharePoint, email [recipients]."

# Release notes
"Draft release notes cho sprint [N] từ merged PRs và
completed Monday stories. User-friendly language."
```

## Chất lượng kiểm soát

### PM vẫn review và approve:
- Business value của Epic có đúng không?
- ACs có testable không (QA Agent sẽ dùng)?
- Story points có realistic không?
- Không có vấn đề chính trị/client nhạy cảm?

### Dấu hiệu cần intervention:
- AC viết chung chung ("System should work correctly") → yêu cầu Agent viết lại cụ thể hơn
- Epic quá lớn (>8 stories) → yêu cầu split
- Duplicate với Epic có sẵn → link thay vì tạo mới

## Đo lường kết quả (sau 4 tuần)

Ghi lại hàng tuần:
- [ ] Thời gian viết Epic + Stories (target: giảm từ 8h → 3h)
- [ ] Số lần QA Agent hỏi lại về AC không rõ (target: giảm 70%)
- [ ] Số Sprint planning phải điều chỉnh sau khi tạo (target: < 1 lần/sprint)
